# PadBridge

同じネットワーク上の iPad から Mac をミラーリングで操作し、Mac の Typeless で音声入力するためのアプリです。

- **PadBridge Host** (Mac): メニューバーに常駐し、画面を iPad に配信して、iPad からの操作を Mac に入力します。
- **PadBridge** (iPad / iPhone): Mac の画面を全画面で表示し、タッチ・ポインタ・キーボードの操作と、Typeless の開始・終了を Mac に送ります。
- **PadBridgeKit**: 両方で共有する通信・映像・入力変換のライブラリです。

Mac にドライバや追加の設定は不要です。Mac 側で必要なのは、アプリごとの権限 (ローカルネットワーク・画面収録・アクセシビリティ。iPad のマイクや Mac のサウンドを使う場合は、システムオーディオの録音も) だけです。

> [!WARNING]
> ペアリングも暗号化も行いません。同じ LAN 上の端末であれば、どれからでも Mac の画面を見て操作できます。信頼できるネットワークでのみ使ってください。

## 必要なもの

- macOS 26 以降の Apple Silicon Mac と、iPadOS 26 以降の iPad
- Mac の [Typeless](https://www.typeless.com/) (音声入力に使う場合)
- Xcode 26
- [Nix](https://nixos.org/) (flake で XcodeGen をこのリポジトリ内だけに用意します)
- [just](https://github.com/casey/just)

## セットアップ

1. `Config/Local.xcconfig.example` を `Config/Local.xcconfig` にコピーし、Apple Developer のチーム ID を記入します。
2. `just run-host` で Mac 側をビルドして起動します。メニューバーに iPad のアイコンが表示されます。
3. メニューを開き、「画面収録」と「アクセシビリティ」を許可します。初回は「ローカルネットワーク上のデバイスの検出」も求められるので許可します。画面収録は、許可したあとにメニューの「再起動」が必要な場合があります。
4. iPad を Xcode とペアリングし (一度 USB で接続し、デベロッパモードを有効にする)、`xcrun devicectl list devices` で ID を調べて `just install-pad <ID>` でインストールします。無料の開発者アカウントの場合は、iPad の「設定 → 一般 → VPN とデバイス管理」でデベロッパ App を信頼します。
5. iPad で PadBridge を開くと、前回接続した Mac か、見つかった Mac が 1 台だけならその Mac に自動で接続します。
6. 蓋を閉じた Mac で iPad のマイクを使う場合は、Mac の「システム設定 → プライバシーとセキュリティ → 画面とシステムオーディオの録音」で、次の 2 つを許可します。
   - 「PadBridge Host」: 初めて iPad を接続したときにダイアログが表示されるので、許可します。
   - 「Typeless」: 自動では一覧に表示されないので、「システムオーディオ録音のみ」の「＋」から追加します。macOS が、このデバイスを使うアプリにもこの権限を求めるためです。権限が足りないときは、iPad で話した直後に iPad に通知が表示され、Mac でこの設定画面が開きます。
   - iPad 側では、初めて Typeless ボタンを押したときにマイクへのアクセスを許可します。
7. 蓋を閉じたまま使う場合は、メニューの「ログイン時に起動」をオンにしておくと、Mac を再起動したあとも Host が起動し、iPad から接続できます。

## 操作

| iPad での操作 | Mac での動作 |
|---|---|
| 1 本指でタップ | クリック (続けてタップするとダブルクリック) |
| 1 本指でスワイプ / 2 本指で動かす / トラックパッドやマウスでスクロール | スクロール (指を離すと止まる) |
| 長押ししてから動かす | ドラッグ |
| 長押しして動かさずに離す / 2 本指で短くタップ | 右クリック |
| 2 本指でピンチ | iPad 上で Mac の画面を拡大・縮小 (最大 5 倍。ピンチしながら動かすと表示位置も動く。縮小しきると等倍に戻る) |
| 3 本指で左右にスワイプ | 操作スペース (デスクトップやフルスクリーンのアプリ) の切り替え (左へスワイプすると右の操作スペースへ) |
| 3 本指で上へスワイプ | Mission Control (もう一度上へスワイプするか esc で閉じる) |
| 3 本指で下へスワイプ | アプリケーションウインドウ |
| 画面の下端から上へスワイプ | Mac の Dock を表示 (iPad で Dock を出すのと同じ操作。Dock が表示中でないディスプレイにあれば、そのディスプレイに切り替える) |
| トラックパッドやマウスのクリック | そのままクリック (副ボタンは右クリック) |
| Apple Pencil でタッチ / タッチしたまま動かす | クリック (続けてタッチするとダブルクリック) / そのままドラッグ (Sidecar と同じく長押しは不要) |
| トラックパッド・マウス・Apple Pencil のホバー | カーソル移動 (Mac の画面上では iPad のポインタを非表示にし、Mac のカーソルだけを表示する) |
| ハードウェアキーボード | そのままキー入力 (Command などとの組み合わせも可。⌘ を押しながらタップすると ⌘クリック)。長押しすると、Mac のキーリピートの設定どおりに繰り返します |

### 画面の構成

Mac の画面を全画面で表示し、操作は次の 2 か所にまとめています。

- **操作パネル**: 画面の隅に浮かぶ小さなカプセルです。ドラッグで好きな隅に移動でき、位置は保存されます。16:9 の外部ディスプレイのように Mac の画面が横長で上下に黒い帯ができるときは、Mac の画面に重ならないよう帯の中に配置します。
  - Enter: Mac の Return キーです。Typeless で話したあと、キーボードを出さずにそのまま確定できます。
  - Typeless (マイク): Mac の Typeless の音声入力を開始・終了します。
  - キーボード: ソフトウェアキーボードを表示・非表示にします。
  - アプリ切替: Mac の Command+Tab です。タップするたびに次のアプリへ進み、1 秒間タップしないと確定します。
  - その他 (…): 表示するディスプレイと最前面のウィンドウの移動 (Mac にディスプレイが 2 台以上あるとき)、Mac のサウンドを iPad で再生 (オン・オフ)、Mac のショートカット (⌘Space・⌘N など、ハードウェアキーボードでは iPadOS が受け取ってしまうもの)、操作一覧 (この README の操作表を iPad で表示)、切断。
- **キーボード上部のバー**: キーボードを表示している間だけ、そのすぐ上に表示されます。
  - esc・Tab
  - 修飾キー ⌃ ⌥ ⌘ ⇧: 押すと次の 1 回 (キー・クリック・ドラッグ) だけ有効になり、2 回続けて押すとロックされます。
  - 矢印キー ←↓↑→: 長押しするとキーリピートします。
  - 英数・かな: Mac の入力モードを切り替えます。現在の入力モードが青く表示されます (Mac 側で切り替えたときも追従します)。
  - ー: 長音記号です。英字配列のキーボードでは - が記号の画面にしかないため配置しています。英数モードでは - になります。
  - ペースト: iPad でコピーしたテキストを、そのまま Mac の入力欄に貼り付けます。キーを 1 つずつ打つのではないので、日本語・記号・絵文字もそのまま入力できます。iOS のペーストボタンなので、ペーストの許可を求めるダイアログは表示されません (ハードウェアキーボードの ⌘V は、これまでどおり Mac のペーストです)。

キーボードで打ったキーは、そのまま Mac に送ります。日本語は Mac 側の日本語入力で変換するので、Mac に物理キーボードをつないでいるのと同じ感覚で入力できます。かなモードでは - , . / ! ? が「ー」「、」「。」「・」「！」「？」になります。削除キーは長押しで連続して削除できます。キーボードを表示すると Mac の画面はキーボードの上に縮小され、入力中の場所が隠れません。

### Typeless で音声入力

操作パネルの **Typeless** ボタンで、Mac の Typeless の音声入力を開始・終了します。

- **タップ**すると開始し、もう一度タップすると終了します。
- **押している間**だけ話し、指を離すと終了する使い方もできます。

Mac は Typeless の設定ファイル (`~/Library/Application Support/Typeless/app-settings.json`) に書かれたショートカットを読み取り、そのショートカットを 1 回押します。ショートカットの設定は読み取るだけで、書き換えません。Typeless が起動していなければ起動し、ショートカットを受け付けられる状態になってから押します。前回の音声入力の文字起こし中で受け付けられなかったときは、押し直します (その間の音声も Mac でバッファしておくので、話し始めが欠けることはありません)。

音声は **iPad のマイク** で入力します。Mac は蓋を閉じると内蔵マイクがハードウェア的に切り離されるため、蓋を閉じたままでも話せるようにするためです。

- iPad が接続している間だけ、Mac に入力デバイス「PadBridge iPad マイク」が表示されます。Mac には何もインストールせず、macOS 標準の仕組み (プロセスタップと機器セット) で作成し、iPad との接続が切れると削除します。
- iPad を接続したとき、Typeless のマイク設定が「自動検出」なら、Host が「PadBridge iPad マイク」に切り替えて Typeless を再起動します。このデバイスは macOS の仕様で Mac のデフォルトの入力にできず、「自動検出」のままでは使われないためです。Typeless は選択したマイクが見つからないと自動検出に戻るので、iPad を接続していないときの使い方は変わりません。iPad が接続していても、iPad から話していない間は Mac のデフォルトの入力の音声をこのデバイスに流すので、Mac で直接 Typeless を使えます。Typeless で特定のマイクを選択している場合は、変更しません。
- 初めて使うとき、Mac で「PadBridge Host」に「システムオーディオの録音」を許可します。許可されていない間は iPad の音声を Mac に渡さず、Mac 側のマイクで音声入力します。
- Typeless がこのデバイスを使うには、Typeless にも「システムオーディオの録音」の権限が必要です (macOS の仕様)。システム設定の「プライバシーとセキュリティ」→「画面とシステムオーディオの録音」の「システムオーディオ録音のみ」に Typeless を追加してください。権限が足りないときは iPad に通知が表示されます。
- iPad のマイクで話している間は、Typeless ボタンの周りのリングが音量に合わせて太くなります。iPad が音声を拾えているかを確認できます。
- iPad 側でマイクへのアクセスを許可していない場合も、Mac 側のマイクで音声入力します。

ボタンの色は、Mac の Typeless が実際に音声入力中か (Typeless がマイクを使っているか) に合わせて変わります。Mac で直接 Typeless を使ったときや、Typeless の ✕ でキャンセルしたときも、iPad の表示はずれません。iPad アプリがバックグラウンドに移ったときや切断したときに止めるのは、iPad から開始した音声入力だけです。

### Mac のサウンド

「…」の「Mac のサウンドを iPad で再生」をオンにすると、Mac のサウンドを iPad で再生します。設定は保存され、次回の接続時にも使われます。

- 再生中は、Mac のスピーカーからは再生されません。iPad アプリをバックグラウンドに移したり、この設定をオフにしたり、接続が切れたりすると、Mac での再生に戻ります。iPad をしまったまま Mac を開いても、Mac が無音のままになることはありません。再生中は、Mac の PadBridge Host のメニューにその旨が表示されます。
- iPad のマイクで Typeless に話している間は再生しません。iPad で再生した Mac のサウンドを、マイクが拾わないようにするためです。
- 無音の間は送信しないので、通信量と iPad のバッテリーを消費しません。再生中も Opus で圧縮して送信するので、約 128 kbps です。
- Mac で「PadBridge Host」に「システムオーディオの録音」の権限が必要です (iPad のマイクと同じ権限です)。

### 外部ディスプレイ

Mac にディスプレイが 2 台以上接続されているときは、「…」の「表示するディスプレイ」で iPad に表示するディスプレイを選べます。ディスプレイ名のあとには、メインディスプレイから見た配置 (「メインディスプレイ」「メインディスプレイの左」など) が付きます。名前を取得できないディスプレイは「名称不明のディスプレイ」と表示されます。

- タッチした位置は、表示中のディスプレイ上の位置として Mac に送られます。ディスプレイの端をタッチしても、ポインタが隣のディスプレイへ移ることはありません。
- ディスプレイを選び直すと、ポインタをそのディスプレイの中央へ移動します。Mission Control のように、ポインタのあるディスプレイに効く操作を、表示中のディスプレイに効かせるためです。拡大していた場合は等倍に戻ります。
- アプリ切替などで前面に出たアプリのウィンドウが別のディスプレイにある場合は、そのディスプレイに切り替えて表示します。このときポインタは移動しません (Mac を直接使っている人のマウス操作を邪魔しないため)。
- 表示するディスプレイが切り替わると、iPad に「(ディスプレイ名) を表示中」が 2 秒間表示されます。
- 画面の下端から上へスワイプして Dock を表示するとき、Dock が表示中でないディスプレイにある場合は、Dock のあるディスプレイに切り替えてから表示します。Dock は 1 台のディスプレイにしか表示されないため、そのままでは見えない Dock にキーボード入力が移ってしまうためです。
- 「…」の「最前面のウィンドウを移動」でディスプレイを選ぶと、最前面のウィンドウをそのディスプレイへ移動し、そのディスプレイを表示します。元のディスプレイでの位置 (左上・中央など) を保ち、収まらない場合は縮小します。
- 最後に表示したディスプレイ (選んだディスプレイのほか、前面に出たウィンドウに合わせたり、ウィンドウを移動したりして切り替わったディスプレイも含む) は Mac が保存し、次回の接続時にもそのディスプレイを表示します。そのディスプレイを取り外したり、蓋を閉じて内蔵ディスプレイが消えたりするとメインディスプレイを表示し、再接続されると再びそのディスプレイを表示します。
- ミラーリング中のディスプレイは、同じ内容が表示されるので 1 台として扱います。
- Mac のメニューバーの PadBridge Host のメニューに、iPad に表示中のディスプレイが表示されます。Mac の前にいる人にも、iPad がどのディスプレイを見ているかが分かります。

### 接続の維持

iPad で別のアプリに切り替えても、接続は切れません。バックグラウンドにある間は映像だけを止め、フォアグラウンドに戻るとすぐに再開します。Wi-Fi の瞬断などで切れた場合も、自動的に再接続します。

Mac の解像度を変えたり、ディスプレイを接続・取り外したり、配置を変えたりしたときは、映像をそのディスプレイに合わせて作り直します。

iPad が低電力モードのときや本体の温度が高いときは、映像を 30 fps に下げてバッテリー消費と発熱を抑えます。

回線が混雑しているときは、iPad に届ききらないフレームを送らずに破棄し、映像の遅延がたまらないようにします。混雑が続くと画質 (ビットレート) を下げてフレームレートを保ち、回線が空くと戻します。大きく下げたときと戻したときは、iPad に短い通知が表示されます。往復遅延が長いだけの回線や、Wi-Fi の遅延のゆらぎ (ジッター) では、画質を下げません。

Mac の画面に変化がなくなると、最後のフレームを何度か送り直して画質を上げます。遅い回線で途中のフレームが残ったり、アプリを切り替えた直後のぼやけた画面のままになったりしません。拡大したまま表示位置を動かしたときも、Mac の画面に変化がなくても新しい範囲が鮮明に表示されます。

## トラブルシューティング

たいていの問題は、iPad の画面に通知が表示されます。通知が出ないものも含めて、確認する順にまとめます。

| 症状 | 確認すること |
|---|---|
| iPad に Mac が表示されない、「接続中…」が続く | 10 秒接続できないと、iPad に「Mac に接続できません」と表示されます。Mac がスリープしていないか (蓋を閉じて使う場合は、スリープさせない設定や Amphetamine など)。iPad の設定で PadBridge に「ローカルネットワーク」が許可されているか (許可されていない場合は、一覧の代わりにその旨と設定を開くボタンが表示されます)。Mac で PadBridge Host が起動しているか (蓋を閉じたまま使う場合は「ログイン時に起動」をオンにしておく)。 |
| 接続できるが画面が黒い | Mac で PadBridge Host に「画面収録」が許可されているか (足りない場合は iPad に通知が表示されます)。許可したあとは Host のメニューの「再起動」。 |
| タッチしても Mac が反応しない | Mac で PadBridge Host に「アクセシビリティ」が許可されているか (足りない場合は iPad に通知が表示されます)。 |
| Typeless が iPad のマイクの音声を認識しない | PadBridge Host と Typeless の両方に「システムオーディオの録音」が許可されているか (Typeless は「システムオーディオ録音のみ」の「＋」から追加する)。足りない場合は、話した直後に iPad に通知が表示されます。Typeless で「PadBridge iPad マイク」以外のマイクを選択していると、そのマイクで音声入力します。 |
| ハードウェアキーボードのショートカットが効かない | ⌘Tab・⌘Space・⌘H・⌘M・⌘N・⌘O・⌘Q・⌘R は iPadOS が受け取ります。「…」の「Mac のショートカット」から送ります。 |
| 見たい画面が表示されていない | Mac にディスプレイが 2 台以上ある場合は、「…」の「表示するディスプレイ」で選びます。Mac のメニューバーの PadBridge Host のメニューに、iPad に表示中のディスプレイが表示されます。 |
| 映像が遅い・カクつく | 「…」の「接続状況」で、Mac が送信している映像の画質、iPad が受信しているフレームレートとデータ量、往復遅延を確認できます (2 秒ごとに更新)。Mac のメニューバーの PadBridge Host のメニューにも、iPad への配信の状況が表示されます。回線が混雑していると画質を下げ、届かないフレームは破棄するので、Wi-Fi の電波が弱い場所ではフレームレートが下がります。 |
| スクロールが指の動きより大きく動く | LinearMouse など、Mac のスクロール速度や加速を変更するアプリの影響が考えられます。Host は iPad からのスクロールを、LinearMouse が処理する段階 (HID のイベントタップ) より後に入力するので、LinearMouse の設定はかかりません。 |
| Mac のサウンドが iPad で再生されない | 「…」の「Mac のサウンドを iPad で再生」がオンになっているか。iPad のマイクで話している間は再生されません。 |
| 「Mac の PadBridge Host と iPad アプリのビルドが一致しません」と表示される | 片方だけを更新した状態です。`just deploy-host` と `just deploy-pad <ID>` で、両方を同じコミットのビルドに更新します。どのビルドが動いているかは、iPad の「接続状況」と Mac の Host のメニュー下部に表示されます。 |

Mac 側のログは、`log show --predicate 'subsystem BEGINSWITH "dev.void2610.padbridge"'` で確認できます。

## 開発

```sh
just test       # PadBridgeKit の単体テスト (通信、HEVC と H.264 のエンコードからデコードまで、遅い回線でのフレームの破棄とビットレート制御、画面に変化がないときの再送、タッチの解釈、キーの配列とキーリピート、修飾キー、Typeless のショートカットの解釈と押すかどうかの判定、Mac のサウンドの Opus エンコードと、バッファしてステレオで再生する処理、ディスプレイの並べ方と選び方)
just test-ios   # 同じテストを iOS シミュレータで実行 (iPad で使う部品が iOS でも動くか。映像のエンコードは Mac だけなので除く)
just test-tsan  # 同じテストを Thread Sanitizer 付きで実行 (複数のスレッドから使う部品のデータ競合を検出する)
just check      # 上の 3 つのテストと、Host・iPad アプリのビルドをまとめて実行 (ビルドは毎回クリーンビルドし、コードの警告が 1 件でもあれば失敗)
just deploy-host  # 起動中の Host を新しいビルドに更新する (Typeless が音声入力中のときと、iPad が接続中のときは更新しない)
just deploy-pad <ID>  # iPad アプリを新しいビルドに更新する (インストールするとアプリが終了するので、iPad が Host に接続中の間はインストールしない)
```

アプリのアイコンは `Scripts/AppIcon.swift` で描画しています。デザインを変えたら `just icon` で iPad と Mac のアセットカタログに書き出します。

検証は、単体テストとビルドで行います。使用中の Mac や iPad のマウス・キー・ウィンドウを操作したり、利用者の操作を監視したりする検証は行いません。

## 既知の制約

- Mac の画面がロックされている間は、映像が止まり、iPad からの入力 (パスワードの入力を含む) が反映されないことがあります。macOS がロック画面のキャプチャと、合成した入力を制限するためです。iPad には「Mac の画面がロックされています」と表示し、ロックが解除されたら映像を作り直します。蓋を閉じて iPad から使う場合は、Mac がロックされないようにしておくと安心です。
- 一度に表示できるディスプレイは 1 台です。ディスプレイをまたいでウィンドウをドラッグすることはできません。ウィンドウを別のディスプレイへ移すときは、「…」の「最前面のウィンドウを移動」を使います。
- ハードウェアキーボードの ⌘Tab・⌘Space・⌘H・⌘M・⌘N・⌘O・⌘Q・⌘R は iPadOS が先に受け取るので、Mac に届きません。アプリの切り替えは操作パネルのアプリ切替を使います。それ以外は「…」の「Mac のショートカット」から送れます (キーボードを表示してキーボード上部のバーの ⌘ を押してから、ソフトウェアキーボードで文字を入力しても送れます)。
